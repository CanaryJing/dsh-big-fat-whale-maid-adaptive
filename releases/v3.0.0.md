# v3.0.0 — 全能工具面：常驻核心 + 按需解锁

## 为什么改

v2 的定位是「全量工具首轮开放」，是给当年不会用工具搜索的 v4 补课。模型换强之后，这个取舍开始只付成本不拿收益：

- 本机 109 个会话、7255 次工具调用的实测分布：**8 个工具覆盖 86.5%**，前 25 个覆盖 97.1%；
- 当前注册目录约 110 个工具，**约四成从装好到现在一次都没被调用过**，却每轮都在发 schema。

所以 v3 把「全能」和「全量常驻」拆开：能力一个不少，但只有高频核心常驻。

## 更新

- **新增 `tool-gate.mjs`**：按会话裁剪 `system-prompt/assemble` 返回的工具目录，只保留常驻核心；其余工具经 `dev_tool_search` 解锁。
- **常驻核心 29 个**（`DEFAULT_RESIDENT_TOOLS`），按实测分布挑选，跨平台并集、缺失名字静默忽略：
  - shell：`gitbash` / `pwsh` / `bash` / `ops_bash`
  - 文件与图像：`read` / `write` / `edit` / `str_replace_editor` / `read_image`
  - 搜索：`grep` / `glob` / `web_search`
  - 任务与交付：`todo_write` / `delivery_check` / `dev_router_status` / `env_probe`
  - 技能：`skill_search` / `skill_load`
  - 记忆读取：`mcp__openviking__read` / `mcp__openviking__search`
  - 交互与目标：`ask_user_question` / `present` / `get_goal` / `update_goal`
  - 后台与协作：`job_output` / `job_list` / `subagent` / `send_message` / `list_agents`
- **`dev_tool_search` 解锁入口**：`query` 搜索全量目录（`ctx.tools.schemas()` 不受裁剪影响），`toolNames` 按精确名解锁，两者可同用；工具描述里带可解锁能力索引（办公文档、记忆写入、仓库工具、多代理、定时任务、终端会话、编排、图像生成、连接器等），防止模型用 bash 硬凑或谎称做不到。
- **解锁状态持久且可恢复**：解锁名写入 `tool/call` 会话事件，冷启动扫描一次即可重建；上下文压缩后仍在内存中，不需要额外存储服务。
- **子代理默认不裁剪**（`includeSubagents: false`）：子代理常被派去跑具体任务，缺工具会卡死；需要时设为 `true`。
- **一键回退**：`mode: full` 恢复「全量首轮可见」，不卸载插件；`mode: progressive`（默认）为门控。
- **安全网**：`dev_tool_search` 未成功注册、或组装结果里没有工具数组时，自动退回全量，绝不把会话锁死；过滤器自身异常同样降级全量并只告警一次。
- **状态自检对齐**：`dev_router_status` 的 `toolCatalog=` 行改由 `describeGate()` 输出真实门控状态（常驻数、已解锁数、门控工具名），不再写死「全量开放」。
- **文档与版本**：README / AI.md / AIreadme.md 同步，`package.json` 升到 3.0.0，新增 `tool-gate.mjs` 导出子路径。

```bash
dsh plugin --profile web add "file:/absolute/path/to/dsh-preset-big-fat-whale-maid-adaptive-3.0.0.tgz"
```

**Tauri 注意：不要以 `file:…tgz` 安装。** 使用源码目录或解压到持久目录，再执行 `dsh plugin --profile tauri add "file:/absolute/path/to/preset-directory"`，并保留目录。Electron `desktop` 请使用桌面版自带的官方 CLI。安装后重启对应宿主。

## 边界

- 门控裁的是**模型可见的 schema**，不是权限：被锁的工具直接调用会得到 `UNKNOWN_TOOL`，解锁后再走原有审批与沙箱策略。
- 常驻名单是静态判断，不按任务动态调整；某个低频工具如果突然变成主力，改 `residentTools` 或先解锁。
- 解锁会使下一次请求的工具列表变化，从而让该段前缀缓存失效；一次解锁多个工具比反复单个解锁划算。
- 子代理不裁剪意味着它们的请求仍带全量目录，成本省在顶层会话。
