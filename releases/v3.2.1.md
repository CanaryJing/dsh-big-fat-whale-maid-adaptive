# v3.2.1 — PTC 门控与解锁恢复修复

修复 v3.2.0 在 PTC 下 high 仅裁剪原生工具列表、SDK 和嵌套调用仍暴露全量工具的问题。

## 2026-10-26 同版本覆盖：首轮与切档时序

旧 v3.2.1 仍在 system-prompt/assemble waterfall 才切档，但引擎在进入该 waterfall 前已采集工具与 section，导致首轮 max 漏发 run_code、SDK 落后一档。现前移至早期变量提供者：先对齐 presentation，再对齐门控，保证本轮 wire schema、SDK 文本和执行范围一致，不修改底座或冻结请求。按用户授权覆盖 v3.2.1 资产和 tag，旧包已留底；重新下载安装、重启宿主后生效。

## 修复

- **run_code 默认保留、无须解锁**：作为 PTC 固定传输入口，不参与能力过滤；其余工具从程序内调用。
- **high 真正按需开放**：生成 SDK 前应用会话级 restriction，同时限制继承工具的 SDK 声明与嵌套执行。
- **max 全量开放但不越权**：撤销本门控的 mask，不移除外部 scope restriction、权限、审批或沙箱限制。
- **搜索与解锁**：仅同步撤下本门控自己的 mask 获取实际目录，立即恢复；其它限制保留。申请解锁后当前程序先返回，下一次 run_code 才绑定新工具。
- **PTC 解锁持久恢复**：识别 tool/ptc-dispatch-start 与 tool/ptc-dispatch，按 root/parent/subcall 配对成功结果，恢复精确 accepted 名单；失败、孤立结果、父调用不匹配、空 accepted 不恢复。
- 保留此前 DeepSeek 全延迟声明兼容修复和 low/native 行为。

## 验证与边界

51 项针对性测试全部通过，0 失败 / 0 跳过。新增真实 SystemPrompt + ToolRuntime + effort-policy + tool-gate 联动，不预先 presentAs、不做首轮预热；两种注册顺序下核查 78 次快照，覆盖首轮 low/high/max、连续切档、模型选择事件、当轮 SDK 文本、wire schema、执行范围、下一次运行解锁与外部限制保留。保留双会话隔离和恢复配对测试。未重新运行全部测试或真实上游付费 API。
