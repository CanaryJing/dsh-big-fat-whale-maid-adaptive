# v3.2.3 — 适配 DSH 0.2.2：移除已被合并的 list-agents 插件行

- DSH 0.2.2 把独立的 `list-agents` 插件并进 `@deepseek-ai/dsh-tool-subagent-control`：根插件现在自己注册 `list_agents`，`./list-agents` 子路径已从 `exports` 移除。
- v3.2.2 的 delegation 组仍保留 0.2.1 时代的 `tool-subagent-list-agents` 行，真实装载解析失败（`ERR_PACKAGE_PATH_NOT_EXPORTED`），装载审计把该行报成 `never started`。
- 本版删除该行，`cordis.patch.yml` 与旧备查 `agent.cordis.yml` 同步。模型能力不变：`list_agents` 由 `@deepseek-ai/dsh-tool-subagent-control` 根行提供。
- `package.json` 增加 `engines.dsh: ">=0.2.2-rc.1 <0.3.0-0"`：0.2.1 及更早内核会被明确跳过并提示，不再以「能装但半残」的方式运行；那些内核请继续用 v3.2.2。
- 新增回归测试 `tests/plugin-resolution.test.mjs`：设置 `DSH_TEST_ANCHOR` 指向已安装 DSH 时，解析 `cordis.patch.yml` 中每个插件名，任何一个不能解析即失败。上游再合并/删除子路径时，这里先红，而不是等用户装载审计报 `never started`。
- 实测：DSH 0.2.2-rc.1 真实引擎组合配置通过（`--dump-config`），`list-agents` 0 处，预设 27 个插件名全部可解析；锚定该引擎 + 真实 PowerShell 7 的全套为 **168 tests / 159 pass / 0 fail / 9 skip**。
- **已知限制（不是本版引入）**：DSH 0.2.2 用执行器插件（`@deepseek-ai/dsh-tool-executor-native` / `-ptc`）取代了 `tools.presentAs()`，同时移除了 `tools.modeFor()`。本版仍沿用 0.2.1 的呈现 API，因此在 0.2.2 上：预设可干净装载，`low` 档行为不变，但 `high` / `max` 会在首次切档时告警一次并回落 `native`（不再切到 PTC）。上面 9 个 skip 就是这批三档行为测试，按能力探测显式跳过并标注原因，等把三档迁移到执行器模型后重新打开。
- 安装后重启宿主再新建会话；若插件管理器缓存了旧包，先卸载再装。
