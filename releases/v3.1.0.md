# v3.1.0 — 路由、交付、工具组与单一 shell 规则

本版在 v3.0 的「常驻核心 + 按需解锁」之上做一组收敛，不引入新依赖、不改变宿主权限模型。

## 1. 路由：最近真实用户请求 + consult

- `sessionMode` 从「第一条 user/message」改为**逆序取最近真实用户实质请求**。
- 兼容 `data.content`、`data.message.content` 与旧 `data.text`；来源白名单为真实用户或旧无 source 数据。
- 排除 `plugin`、`plugin:*`、`agent-message`、`model-selection`、`user-approval` 等自动通知；`openviking-context`、`runtime-context` 等包装块会被剥离，同一消息包装外的真实请求保留。
- 最近一条只是「继续/好的/可以」等简短应承时，沿用上一实质任务；没有上一实质任务则 weak。
- 新增 `consult`：明确问句（「如何修复这个错误？」「Why create this file?」）即使含 fix/build 也先回答；解释、评审、分析、只读、先给计划不催写代码。明确的实施意图仍进入 react/spec；「按计划实现修复」应实施。
- **范围限制不等于完全禁止实施**：「只做这个错误的修复」「修复这个错误，不要改其他文件」仍走 spec；只有「不要写/不要改」这类没有正面实施请求的指令才 consult。
- 多段 `Current runtime context` 快照整块剥离到消息末尾，不会只删标题段后让 `Current working directory` / `You are…` 覆盖真实任务。
- 英文动词/问句按单词边界匹配，`address`/`prefix`/`typewriter`/`somehow` 不会误命中 add/fix/write/how。
- 代码块/引用块不参与意图计数，避免 quote/code 注入误触发，但包装外的真实实现请求保留。
- 没有可靠意图时返回中性 `weak`，不默认 react。overlay 明确声明只是风格提示、不授予权限；用户请求、计划模式、审批规则优先。

## 2. delivery_check：基础文件与证据检查收紧

- 输入仍为 `file` / `evidence`，输出仍为 `ok` / `checks`。
- 修复 JSON Schema 转换：子对象的 `required` 数组只表示该对象内部必填，不再把字段加进父对象；只有 `required: true` 才让父对象要求该字段。缺 `type` 时省略 `type`，不生成非法 `type: "any"`。`delivery_check` 的 evidence spec 用 `required:true`（父级）与 `items.required=true`（evidence 内部）表达两层要求。
- 相对路径只按 `exec.agent.session.header.cwd` 解析；没有会话 cwd、相对 cwd、Windows drive-relative（`C:foo`）、root-relative（`\foo`、`/foo`）及外部平台绝对路径都 FAIL，绝不退回 `process.cwd()`。
- 文件必须是普通、非空、可读文件；未知扩展名也验证可读性。格式读取异常统一转成 FAIL check，不抛穿工具。
- 按扩展名分型：
  - 文本严格 UTF-8（`TextDecoder` fatal）；超过明确校验上限 FAIL，不做部分解码；
  - PNG/JPEG/GIF/WebP 查签名与基本截断；PDF 查 `%PDF-` 头与 `%%EOF` 尾；
  - docx/xlsx/pptx 只读 ZIP central directory 与必要 local header，校验 `[Content_Types].xml`、`_rels/.rels` 和对应主文件；不解压、不执行。拒绝条目 data 覆盖 central directory、local 范围重叠、声明区域未消费完、越界/伪造/过限；
  - 未知扩展名只做文件/证据检查，并明确报告 format 未验证。
- 证据 item 必须有合法 kind、非空 label 与 result。file/page/image/run/test 还需本地普通可读非空 target，并按会话 cwd 解析、记录 SHA256（流式读取，避免无界内存）。
- `page`/`image` 的 `reviewed:true` 仍是**人工审阅声明**，但 target 必须是可识别图片并通过基础签名检查；文本日志/HTML/未知扩展不能冒充截图。
- **图片/PDF/docx/pptx 页面交付**至少需要一项 accepted `page`/`image` 且 `reviewed:true`；xlsx 维持数据/测试证据即可。text-only 证据不能通过这些视觉交付。
- run/test 只核查日志存在与结果声明，不执行日志。external 只验证合法 http(s) URL 与 result，不联网。numeric/text 需要 result。
- 所有 PASS 都附带 `scope` 说明：只代表基础文件与证据检查，不保证语义正确、视觉质量、完整格式合规或外部事实真实。

## 3. dev_tool_search：固定工具组与 accepted 精确持久化

- 新增可选 `groups: string[]`，保留 `query` / `toolNames` 调用方式。
- 固定组：
  - `office`：`office_*`
  - `repo-files`：`ops_inspect_local_file` / `ops_grep` / `ops_glob` / `ops_replace` / `ops_write_file` / `ops_edit_file` / `ops_diff` / `ops_stat` / `ops_copy` / `ops_move` / `ops_remove`
  - `sessions`：`session_search` / `session_trace` / `session_event_*`
  - `team`：`spawn_teammate` / `team_task_*` / `wait_agent` / `interrupt_agent` / `send_message` / `list_agents`
  - `terminal`：`terminal_*`
  - `memory-write`：`mcp__openviking__*` 除 read/search
- 组只基于 `ctx.tools.schemas(exec.agent)` 的实际目录展开；精确名与组展开合并去重；未知组明确报告，合法项继续；空组说明当前 scope 没有可解锁工具。
- 仅改变可见性，不授予权限，也不绕过 scope。
- 成功解锁的实际 accepted 精确名通过官方 tool-private `tool/result.meta` 持久化（`output.presentationMeta`），不凭空 append 未注册事件。冷启动/压缩后按精确名恢复，恢复时绝不重新展开组。
- 恢复只信**与本会话一条 `dev_tool_search` callId 配对成功**的 result：其它工具的文本/meta、伪造 `gate` 名、映射到非 gate 调用的结果都不会解锁。
- v3.0 固定成功文案仍需配对 call 才恢复；没有 meta 的旧成功结果不再按请求 `toolNames` 全量回退。
- 没有 result 的 `tool/call` 无法区分成功与中断，保守保持锁定；这类旧日志需要重新调用 `dev_tool_search`。
- 没有 `agent.session` 时 `execute` 返回 `accepted: []` 并明确说明未解锁、可持久化会话不存在。
- 无参概览列出固定组及用途。搜索说明修正为「任一关键词命中即参与打分」，不是全部关键词 AND。

## 4. Shell 规则单一来源

- 新增 `shell-policy.mjs`：环境简报、系统提示词 section、gitbash/pwsh/bash（WSL）工具描述共用同一段规则。
- Windows 通用执行优先 Git Bash；**Git Bash 不可用时由已验证绑定的 pwsh 处理 Windows 通用任务**，pwsh 同时负责 PowerShell 专属命令、`.ps1`、Windows UI 自动化；**bash 只用于 Linux-only 工作，绝不是 Windows 回退**；原生 Linux/macOS/Android 用 native shell。ops_bash 只在适用环境能力明确时作为执行入口，不与 Windows 首选竞争。
- persona 只写一句引用该 section 的短句，不再复制路由表，避免两处漂移。
- 目录非法停止；命令失败不换旧 PowerShell/不同 shell；权限拒绝不可越过。
- 独立 section（`whale-maid:shell-routing`）order 改为 **10300**：位于引擎内置 `WEB_SURFACE`(10100) 与 `DEPLOYMENT_PERSONA_SUFFIX`(10200) 之后。真实 `SystemPrompt` 组装测试验证了实际渲染顺序，而不是只断言 mock 的 order 字段。它优先于宿主外部插件的泛化 shell 建议，但不覆盖权限、审批、沙箱、计划模式与文件规则。未修改宿主 `node_modules`。
- `ENV` / `MODEL` section 与 persona 均保留。

## 已知边界

- `delivery_check` 不是安全门禁，也不是文档渲染器/完整 ZIP 解压库；仅做基础文件、格式签名、central directory 结构与证据声明检查。
- 图片不解码像素；视觉 evidence 只做签名/格式检查，`reviewed:true` 不能替代真实人工审阅。
- external 只做 URL 语法检查，不联网验证；run/test 不执行日志。
- 没有 result 的旧 `tool/call` 无法恢复成功解锁，需要重新调用 `dev_tool_search`；这是刻意的保守行为。
- shell 路由是提示词约束，不替代宿主权限、审批、沙箱；宿主外部插件的工具描述不在本包修改范围。
- 安装是快照，升级后需重新安装并重启宿主；运行中的旧实例不会自动热更新。
