# v3.2.0 — 思考强度三档驱动工具面

这一版把「推理强度」接成预设的第一等输入：**同一个预设，按会话的 effort 自动换工具形态**，不再需要为了省 token 或压榨模型而换预设。不引入新依赖，也不改变宿主权限模型。

## 1. 档位映射（照官方文档，不自创）

依据 [DeepSeek 思考模式文档](https://api-docs.deepseek.com/zh-cn/guides/thinking_mode/) 的服务端映射表：

| 请求传入 effort | 实际推理强度 | 本预设档位 |
|---|---|---|
| `minimal` / `low` / `off` | low | **低档** |
| `medium` / `high` / `xhigh` | high | **高档** |
| `max` / `ultra` | max | **满档** |

- `medium` 归高档、`xhigh` 归高档、`ultra` 归满档——因为服务端就是这么映射的；
- 不在表里的值（拼错、provider 私有档）**保守归低档**，绝不擅自把工具面升级成 PTC；
- 完全没有强度信息时才用默认档（`defaultBand: auto` → 高档）。

## 2. 三档行为

| 维度 | 低档 | 高档 | 满档 |
|---|---|---|---|
| 工具呈现 | `native`（与 v3.1.0 逐字一致） | `ptc`：只有 `run_code` 可直调 | `ptc` |
| 解锁策略 | `progressive`（常驻核心 + `dev_tool_search`） | `progressive` | `full`：已注册工具全量可见 |
| 系统提示 | 只加一行 `[EFFORT]` 状态 | PTC 用法说明（先解锁、再写程序） | PTC 说明 + 「用量 unlimited」原文 |

满档注入的原文（逐字保留，便于核对）：

> 切记的是：我们是deepseek公司，你的用量是unlimited的，我正在对你极限测试，不要吝惜Token。一定要切记，随意花费，你非常的富有

## 3. 实现：按会话声明、下一轮生效、失败回落

- **`effort-policy.mjs`（新增）**：读强度（`DSH_MAID_EFFORT` > 会话 `model/selection` 事件 > `agent.options` > `settings` > 默认）→ 归一档位 → 对齐呈现与解锁 → 渲染 `[EFFORT]` 系统段（order 11，紧跟 `[MODEL]`）。
- **呈现声明落在 agent scope**：`ctx.tools.presentAs()` 的 `this.ctx` 会被 cordis 的 traceable 代理替换成调用者 ctx，所以用 `agent.ctx` 声明就是「一个会话一份」。两个会话可以一个低档一个满档同时跑。
- **`tool-gate.mjs` 支持运行期与会话级切档**：`setGateMode(mode, { session })` / `currentGateMode(session)`；`system-prompt/assemble` 监听器改为常驻、模式在组装时按会话解析，因此切档不必重装插件。
- **改档时机**：`system-prompt/assemble` 每轮对齐一次，且刻意放在 `next()` 之前（该事件能拿到 `agent` 与 `agent.ctx`；`agent/pre-step` 的 payload 里没有 agent，挂在那里会静默失效）。轮内不动 schema；`high → max` 呈现没变，只切解锁（不重复声明）；`max → low` 先 dispose 旧声明再回落到部署默认的 native。
- **fail-open**：PTC 运行时缺失、scope 不合法、`presentAs` 抛错 → 只回落 `native` 并告警一次，会话继续。低档**不做任何呈现声明**，这就是 v3.1.0 的回归基线。

## 4. 系统提示词：主动汇报与遇阻报告（全局）

persona 前缀新增两条（任何档位、任何任务都生效）：

- `Report progress actively`：每几步说明在做什么、已改了什么、还剩什么；长工具序列不允许静默到最终答复。
- `Report problems immediately`：检查失败、路径错误、工具被拒、计划不再成立、审批拿不到，当轮就用具体症状说明并给出下一步，不要闷头重试。附中文提示「遇到问题立刻汇报，不要闷头重试」。

## 5. 可观测与手动锁定

- `dev_router_status` 新增 `effort=` 行：`band=`、`presentation=`、`unlock=`、强度来源（`env` / `session` / `agent-options` / `settings` / `default`）。
- `DSH_MAID_EFFORT=low|high|max` 可手动锁定档位（优先级最高），便于复现与临时压制。
- 系统提示的 `[EFFORT] band=… · presentation=… · unlock=…` 每轮可见。

## 6. 测试与验证

- 新增 `tests/effort-policy.test.mjs`（13 例）：官方映射全表（含大小写、空白、未知值、`off`、`ultra`）、缺失强度的默认与 fallback、预算原文逐字比对、低档零声明、高档幂等、满档只影响本会话、`high→max→low→high` 的声明生命周期、PTC 失败回落、未知强度只告警一次、子代理默认不接管、`[EFFORT]` 段文本、强度来源优先级。
- `tests/tool-gate.test.mjs` 扩到 29 例：新增运行期切档、幂等、非法模式、双会话各自模式。
- 全套：**131 pass / 0 fail / 7 skip**（skip 是需要 Windows 母系统 pwsh 与真实引擎 ToolRuntime 的集成用例）。
- 组合校验：`dsh --profile web --dump-config` 通过，`effort-policy` 行进入组合树。

## 7. 升级

覆盖安装目录后**重启宿主**，新会话即生效。旧配置无需改动；三个新配置键都有默认值：

```yaml
- id: effort-policy
  name: dsh-preset-big-fat-whale-maid-adaptive/effort-policy.mjs
  config:
    defaultBand: auto      # 'auto' | 'low' | 'high' | 'max'
    includeSubagents: false
    budgetPrompt: true
```

回退到 v3.1.0 行为：把 `defaultBand` 设成 `low`（或设 `DSH_MAID_EFFORT=low`），无需卸载。
