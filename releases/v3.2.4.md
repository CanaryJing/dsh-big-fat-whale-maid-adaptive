# v3.2.4 — 恢复 DSH 0.2.2 的 PTC 档位联动

## 修复

- 0.2.2 已用独立工具执行器取代 `tools.presentAs()` / `modeFor()`。预设改用当前引擎的官方 NativeToolExecutor / PtcExecutor，恢复 high＝PTC＋按需解锁、max＝PTC＋全量工具；low 仍为原生工具＋按需解锁，effort 归一规则不变。
- 每个 agent scope 使用稳定执行器，在工具声明收集前对齐当前档位；首轮直接出现 `run_code`，双向切档不落后一轮。
- SDK 与程序绑定共用门控快照：程序中调用 `dev_tool_search` 只影响下一次请求，不能在当前程序调用刚解锁工具；解锁和 high→max 不再受前一轮 registry mask 影响。
- 新执行器不改写共享注册表或宿主文件，保留条件工具 admission、祖先限制、已移除工具检测、权限守卫、审批与沙箱边界。旧 0.2.2 waterfall 工具过滤失效导致的 low 档裁剪问题一并修复。
- `effort-policy.apply` 改为不可构造回调，确保 Cordis 等待异步执行器初始化；初始化/组装失败显式报错，不再出现声明 PTC 却静默回落 native 的状态。

## 验证范围

新增 `tests/executor-022.test.mjs`，使用 DSH 0.2.2-rc.1 的真实 Cordis 严格注入装载、SystemPrompt、ToolsService 与 native/PTC 执行器，覆盖两种插件注册顺序、三种首轮档位、双向切档、SDK/程序绑定、下轮解锁、直接调用拒绝、同预设会话隔离、成功配对 PTC 日志恢复、条件 admission、移除工具与权限守卫。该组使用可控测试 PTC runtime，不等同真实上游模型端到端验收。旧 0.2.1 呈现 API 专用测试在新引擎上仍显式跳过，不计为通过。

本机完整测试：**176 tests / 167 pass / 0 fail / 9 skip**（9 个为旧 API 专用测试）；所有运行模块通过 `node --check`，`git diff --check` 无错误。

## 安装

需要 DSH `>=0.2.2-rc.1 <0.3.0-0`；旧内核继续使用 v3.2.2。通过市场或对应宿主官方插件管理器安装本次 Release 的 tgz，然后重启对应宿主。发布新版不会热替换正在运行的旧模块。不重启当前承载会话的进程。
